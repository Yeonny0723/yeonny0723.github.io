제품의 여러 레이어를 잇는 개발자

팀과 제품의 성장을 우선하고, 배우고 공유하는 문화를 즐기며, 호기심을 바탕으로 업무의 경계를 넓혀 왔습니다. 프론트엔드의 사용성, 백엔드의 안정성, AI의 가능성과 운영 효율이 만나는 지점에서 실제로 동작하는 제품을 만듭니다.

제가 중요하게 보는 것은 새로운 기술을 사용하는 것 자체가 아니라, 복잡성을 어떤 경계와 검증 기준으로 나누어 제품의 변화 가능성과 운영 안정성을 함께 확보하는 일입니다.

## 제가 개발을 확장해 온 기준

- **Frontend** — 복잡한 상태와 비즈니스·도메인·UI 로직을 기능 단위로 나누고, 사용자가 끝까지 완료할 수 있는 흐름을 설계합니다. 모노레포·디자인 시스템·자동화된 E2E로 변경하기 쉬운 단위를 만들고 빠른 피드백을 확보합니다.
- **Backend / Domain** — 레거시를 한 번에 바꾸기보다 하위 호환과 고객사 운영 환경을 고려해 결합도를 낮춥니다. 데이터 모델·MSSQL 쿼리·트랜잭션·동시성·실패 복구를 하나의 도메인 흐름으로 봅니다.
- **AI Application** — LLM에 위임할 작업과 코드·규칙이 책임질 작업을 구분합니다. 비동기 처리·Polling·Queue/Worker·프로세스 운영을 갖추고, 평가셋·모델 비교·비용 가드로 불확실성을 운영 가능한 기준으로 바꿉니다.
- **Product Operations** — 보안은 마지막 점검 항목이 아니라 기획·개발 단계의 제품 조건입니다. 인증·권한·멀티테넌트·Zero Trust·외부 콘텐츠 처리·고가용성·장애 복구까지 사용자 흐름의 일부로 설계합니다.

이 경험들이 결합되면서 화면만 만들거나 API만 연결하는 데서 멈추지 않고, 사용자가 실제로 완료하는 일과 그 뒤의 데이터·권한·비동기 작업·검증·배포까지 이어서 판단할 수 있게 되었습니다.
