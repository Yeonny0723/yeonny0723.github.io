# 보안 제품에서 배운 제품 개발

문서보안 협업 솔루션과 보안교육·피싱 훈련 제품을 개발하며, 기능이 동작하는 것만큼 누가 어떤 권한으로 무엇을 볼 수 있는지가 제품의 완성도를 결정한다는 기준을 갖게 되었습니다. 고객사·테넌트별 제품 활성화와 권한, OTP/MFA와 Zero Trust 인증, DRM 문서 정책, 외부 콘텐츠 표시, AI 검색·생성 결과, npm 의존성까지 서로 다른 위험을 화면·API·데이터·운영 환경의 경계로 나누고 안전한 기본 동작과 검증 방법을 함께 설계했습니다.

M365 Web Add-in에서는 Graph API와 테넌트 컨텍스트를 제품 기능과 분리하고, Mind-SAT에서는 인증·교육·통계 흐름과 훈련 메일 콘텐츠를 연결하면서 CSP·DOM Sanitizing으로 실행 범위를 제한했습니다. AI 서버는 고가용성 구조와 장애 복구를 적용했고, 팀 개발 환경에는 install script·lockfile·semver·dependency tree를 점검하는 공급망 보안 플러그인을 만들었습니다.

이 경험을 통해 보안을 마지막 검수 항목으로 추가하는 대신, 기획 단계에서 권한 경계와 실패 시 기본 동작을 정하고 구현 단계에서 자동 검증과 사람의 승인 지점을 남기는 방식으로 제품을 만들게 되었습니다. 제품 보안과 개발 환경 보안은 대상은 다르지만, 위험을 미리 분리하고 재현 가능한 검증을 설계해야 한다는 점에서 같은 개발 원칙으로 연결됩니다.
