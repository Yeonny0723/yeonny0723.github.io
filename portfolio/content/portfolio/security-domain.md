# 보안 제품에서 배운 제품 개발

현재 회사에서 문서보안 협업 솔루션과 보안 교육·피싱 훈련 제품을 개발하며, 기능이 동작하는 것만큼 누가 어떤 권한으로 무엇을 볼 수 있는지가 중요하다는 기준을 갖게 되었습니다.

## 제품 보안의 복잡성

- 고객사와 테넌트별로 제품 활성화·권한·설정이 달라지는 멀티테넌트 환경
- OTP/MFA와 Zero Trust를 포함한 인증 흐름
- DRM과 연결된 문서 권한 정책
- 훈련 메일·외부 콘텐츠를 화면에 표시할 때의 CSP와 DOM Sanitizing
- 문서 검색·생성 결과가 원문 근거와 제품의 보안 경계를 벗어나지 않도록 하는 검증

이런 환경에서는 프론트엔드에서 버튼을 숨기는 것만으로 충분하지 않습니다. API와 데이터 모델의 권한 경계, 실패했을 때의 기본 동작, 외부 콘텐츠를 표시하는 방식, 고객사별 운영 설정을 함께 확인해야 합니다.

## 제가 맡은 역할

M365 Web Add-in의 Graph API·테넌트 컨텍스트, Mind-SAT의 인증·교육·통계 흐름, 악성 메일 콘텐츠 정제, AI 서버 고가용성 구조를 개발했습니다. 보안 요구를 마지막 검수 단계가 아니라 도메인과 사용자 흐름을 설계하는 조건으로 다뤘습니다.
