# 제품을 만드는 방식

기능의 화면만 구현하지 않습니다. 사용자가 어디서 시작해 어떤 상태를 거쳐 완료하는지 먼저 보고, 그 흐름을 지탱하는 API·데이터·권한·배포·검증 기준을 함께 설계합니다.

제가 반복해서 확인하는 질문은 세 가지입니다.

1. 사용자가 실제로 완료하려는 일은 무엇인가?
2. 어느 판단을 LLM에 위임하고, 어느 판단을 코드와 운영 기준이 책임져야 하는가?
3. 실패했을 때 어디서 멈췄고, 어떻게 재현·복구·검증할 수 있는가?

프론트엔드의 사용성, 백엔드의 안정성, AI의 가능성과 운영 효율이 한 제품 안에서 만나야 한다고 생각합니다. 그래서 UI 상태, 도메인 경계, 비동기 작업, 검색 품질, 비용, 권한, 보안, 테스트와 배포를 서로 떨어진 체크리스트가 아니라 하나의 제품 흐름으로 봅니다.
